# Q1 历史算法组合诊断

本轮分析范围为两个可按完整 100 图、2—5 核、12 候选机会配对的版本：`routes_gate_reuse` 与 `component_local_rank`，共800次搜索、9600条候选记录。没有混入候选预算或覆盖范围不同的开发实验，因此事后收益仅适用于这两个版本的候选并集，不能声称覆盖全部历史提案或所有可行方案。

运行命令（仓库根目录，标准库即可）：

```powershell
python 程序/q1_portfolio_profile.py --output 图表/runs/新诊断目录
python 程序/q1_portfolio_budget.py 图表/runs/新诊断目录
```

输入需已按官方附件导入并通过 `q1_io.verify()`。程序检查两批来源ZIP与硬件配置哈希一致、每配置图文件哈希和固定单核基准一致、每次搜索12机会、最终日志最短周期与保存的官方评价一致。候选级结果来自搜索日志；未把未保存方案的代理值冒充官方结果。

选择器离线验证固定为按case哈希分成五折，全部核数跟随同一图进入一折；训练折只拟合一层决策树，阈值限定训练特征四分位点、每叶至少10张图。目标为平均归一化执行周期，候选动作是选择一个完整历史算法。五折都选择当前算法，因此本轮没有提出不同于当前默认的可上线选择规则，也没有必要重跑相同的400配置冒充新验证。

本轮结论：两个现有完整版本之间几乎没有可利用的互补；后续应先做候选机会的受控替换，不能预期仅套一层选择器就显著提速。建议下一实验保留当前默认和后四次搜索，单独审查 `grain_2.0` 机会的状态依赖，再用一个结构不同的初解替换；固定总预算，记录被移除候选对后续状态的影响。这只是下一实验建议，本轮未修改求解器、未改变正式成绩。

文件说明：

- `report.md/json`：指标、分组交叉验证规则、来源审计和限制。
- `graph_profile.csv`：100图的结构特征。
- `configuration_profile.csv`：400配置的两版本结果、事后择优和测试折选择。
- `candidate_ledger.csv`：9600条候选记录、耗时、指纹和条件边际贡献。
- `budget_by_configuration.csv`、`budget_by_family.csv`、`budget_profile.json`：预算使用画像。

历史耗时来自本机和服务器，且只覆盖搜索阶段，不包含统一的冷启动和最终复核。不能据此把候选耗时相加、相减后宣称真实单机加速。按顺序计算的候选边际贡献也不是删去该候选的因果试验。
