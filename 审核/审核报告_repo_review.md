## 执行摘要

**问题一（场景A）建模概要**：采用固定整图启发式单核基准，多核方案通过划分非COPY算子到子图、映射子图到核心、核内Task串行调度实现。每个子图独立形成一个Task，同核跨Task清空私有缓存，所有跨子图数据经DDR中转。加速比定义为 S(i,n) = T_single(i) / T_multicore(i,n)，100图平均加速比采用逐例比值的算术平均。

**问题二（场景B）建模概要**：继承问题一场景，改为同核所有子图组成一个Task，同核缓存不随子图切换清空，跨核通信有500周期释放延迟。加速比定义与问题一相同，采用固定问题一单核基准作为分母。

## 复算并解释结果

### Q1加速比验证

**实际计算**（基于all_case_results.csv）：
```
5核平均加速比 = (1/100) × Σ(single_makespan / makespan)
                = 3.6659 （实测awk计算）
                = 3.665903 （aggregate.json官方值）
```
**误差**: 0.0008% — 属于浮点精度范围 ✓

**异常检查**：
- 5核加速比>5的算例：10个（case_021/030/033/034/042/059/074/076/079/097）
- 最高加速比：case_059为5.501
- **理论解释**：单核baseline=233110 cycles，5核多核=42361 cycles；单核有大量溢出，多核划分减少溢出和通信开销
- **不违反Amdahl定律**：该定律假设固定baseline是最优串行执行，但题目baseline是启发式，允许改进

**退步算例**：
- case_006三核：31819→32925（+3.47%）
- case_006四核：31094→31129（+0.11%）
- 占比：2/400 = 0.5%
- **合理性**：有界启发式搜索，预算机会被新候选占用可能损失原有效路径

### Q2加速比验证

**r07五点加速比**：1.000000, 1.981113, 2.815714, 3.550822, 4.159974  
**相对r05**：400配置13胜387平0负  
**代价**：总周期下降0.006655%，额外搬运增加0.028884%

**合理性检查**：
- 字典序目标(Makespan, bytes)允许此权衡 ✓
- 几何平均周期比改善0.327737%，与总周期变化不同权重 ✓
- 不能混用三种聚合方式（逐例算术平均、总周期比、几何平均） ✓

### 理论边界场景（未实测，仅理论分析）

**场景1：零通信纯计算图**  
- 理论：N核理想加速比接近N
- 实际：仍有任务等待100周期、DDR读参数开销
- 本仓库无此类极端case

**场景2：全通信无计算图**  
- 理论：DDR带宽60 bytes/cycle成为瓶颈
- 实际：多核并发可能触发带宽共享，加速比<2
- 本仓库case_003等大搬运图接近此情况（5核加速比仅2.05）

**场景3：单一关键路径极长**  
- 理论：Amdahl串行部分限制，加速比<N
- 实际：划分可能破坏关键路径，引入额外等待
- 本仓库有部分case体现（如case_003）

**场景4：极小缓存频繁Spill**  
- 理论：多核划分减少单Task工作集，降低溢出
- 实际：可能出现超线性加速比
- case_059/097体现此现象

**场景5：多消费者共享Tensor**  
- 理论：同核可复用缓存（场景B），跨核需重复COPY（场景A）
- 实际：场景A所有跨Task都经DDR，同核也不免费
- 实现正确

## 评委最可能追问的3个具体问题

### 问题1：为什么5核加速比能超过5？

**回答**：
- 单核baseline采用整图启发式调度，存在大量缓存溢出
- 多核划分后，每个Task的工作集减小，溢出显著降低
- 例如case_059：单核额外搬运10.08 MiB（溢出），5核仅4.39 MiB
- 这符合题意：题目未规定baseline必须是最优单核执行
- Amdahl定律假设固定最优串行部分，不适用于可改进的baseline

**证据位置**：
- all_case_results.csv：10个5核算例>5
- 建模报告.md:48："单核基准还存在启发式导致的溢出，多核划分后的溢出为零"

### 问题2：端到端耗时是否全部≤10分钟？

**回答**：
- **未完成全量验证**，仅验证case_001/014/091部分核数
- case_014五核冷启动156.221秒，case_091五核147.467秒（不含额外复核）
- 全量400配置最大搜索耗时363.859秒（热baseline，不含冷单核和复核）
- 历史大图case_091单核曾超10分钟（改进前）
- **建议**：论文中标注"部分算例验证"或完成剩余验证

**证据位置**：
- 审查/问题一端到端耗时核查_r02.md
- 审查/问题一交付与赛题要求核对_r02.md:54

### 问题3：Q2相对Q1改进了多少？r07相对r05改进是否显著？

**回答**：
- **Q2 vs Q1**：平均加速比从Q1的3.666提升到Q2的4.160（5核）
