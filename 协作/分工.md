# 三人分工与文件责任

三位真人分别操作 A、B、C 三个 Agent。姓名与 GitHub 账号暂用占位；任何 Agent 都不能冒充另一位操作者接收任务或确认人工验收。完整流程见 [正赛协作协议](正赛Agent协作协议.md)。

| 工作端 | 真人姓名 / GitHub | 主责 | 交付与接收 |
| --- | --- | --- | --- |
| A 主控求解与整合 | 待填 | 题意、数据、模型、代码、求解、结果检查、派稿、全文审核与整合 | 每问交 B；收取 B/C 有效章节和审查记录 |
| B 章节写作 | 待填 | 按 A 的证据与要求编写逐问章节，按 C 意见修订 | 接 A，交 C，回复修改，最终交 A |
| C 格式审查 | 待填 | 审查章节源稿与实际渲染页，反馈 B 并复查 | 接 B，反馈 B，审查记录供 A 查阅 |

## 写入和集成

- 三端使用独立 clone/worktree 和任务分支；禁止并发写同一物理目录。
- A 确定 B 的章节文件及允许修改范围；B 不修改正式模型、代码或结果。C 不直接覆盖 B 的章节。
- A 维护全篇入口、公共文献、符号及图表接口，并集成经核对的章节。C 的格式审查不能代替 A 的内容终审。
- A 端承担统筹责任，由该端责任人串行管理唯一阶段状态。其他两端查询状态，不合并各自运行形成的状态 JSON。
- 人工确认和 Agent 检查分开记录；提交方不能代填接收方的 ACCEPTED。

| --- | --- | --- | --- |

## 旧职责名称的对应

早期文档中的 O 是统筹、M 是建模、E 是编程、W 是写作职责，并非另外四名人员。当前 A 覆盖统筹、建模、编程与全篇整合；B 承担逐问写作；C 承担章节格式审查。历史记录不改写，当前实际分工以本页及正赛协议为准。
