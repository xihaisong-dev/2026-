# 每问写作与结果核对

这组表用于把优秀论文研读结论落实到日常写作，当前均为空白模板，尚无正式赛题、实验结果或验收结论。依据见 [优秀论文研读与2026写作指南](../赛前研读/优秀论文研读与2026写作指南.md)。

- [逐问写作卡模板](逐问写作卡模板.md)：每个实际子问题一张，梳理任务、机制、求解、结果、验证与解释。
- [结果数值核对表模板](结果数值核对表模板.md)：用稳定的 `claim_id` 串起结果来源、计算口径、论文各处数值及人工复核。

## 何时填写

| 时点 | 填写动作 | 主填 → 接收 |
| --- | --- | --- |
| 读题后 | 按实际题数复制写作卡为 `Q1-写作卡.md` 等；记录题面位置、输出、约束与上下问依赖 | M → E/W |
| 建模时 | 从正式 `建模报告.md` 引用模型身份、假设、数学关系和求解路线；比较、验证、应用问注明继承模型 | M → E/W |
| 有效运行后 | E 复制结果表为 `结果数值核对表.md`，逐条填来源、原始精度数值、单位、比较条件和验证证据 | E → M |
| 写正文时 | W 登记每条结论在正文、表格、图注中的位置；结果变更先更新事实源，再更新所有引用 | W → M/E |
| 定稿前 | 最后撰写摘要；从有效结论中选每问少量核心结果，补齐摘要位置，由另一名实际队员独立核对 | W → M/E，O 收口 |

所有路径以仓库根目录为基准。这里是协作索引，正式题意、模型和结果仍分别归入 `问题分析.md`、`建模报告.md`、`图表/全部结果.json`；不得在本目录另建一套模型或结果事实源。

O/M/E/W 保留职责占位。正式参赛人员与兼任安排按研读报告中的三名正式队员要求执行；不同角色由同一人兼任时，改换角色名不构成独立复核。实际姓名填内部协作记录，不复制到匿名论文中。

## 结果如何登记

1. 一个 `claim_id` 对应一条明确结论，建议采用 `Q1-C001`，后续修订保留编号。不同数据集、规模、方法或指标分别登记，不能拼成一个“总体最好”。
2. 结果表使用三张关联表：来源、显示位置、验证。各表靠 `claim_id` 关联；一条结论在摘要、正文和图表多次出现时，显示位置表逐处登记。
3. `JSON Pointer` 填实际结果文件中的路径。例如 `/questions/Q1/metrics/value` 仅说明路径语法，不规定结果结构；对象键中的 `~` 和 `/` 分别转义为 `~0` 和 `~1`，数组索引从 `0` 开始。文件尚未生成时填 `NOT_RUN`，不得先编造指针。
4. 原始值保留实际精度；改善幅度先用未舍入值计算，再统一显示位数。源值、单位换算、百分比和各处文字均要核对。
5. “尚未检查”填 `NOT_RUN`；确实不适用填 `N/A + 原因`；发现问题填 `需修订`。模板里的勾选框、空白和占位符都不代表检查通过。
6. 来源文件、运行、模型、输入数据或论文版本变更后，受影响记录转为 `待复核`，复核人重新填写日期和证据，不能沿用旧通过结论。

## 填写边界

- 不强制每问新建模型或目标函数。优化问题给目标与约束；机理问题给状态、关系、边界；理论问题给命题与证明；验证/应用问题写继承关系和新增任务。
- 验证方式服从任务：可行性回代、独立仿真、独立测试、理论证明、小规模精确解、敏感性或消融按需选取，并记录未验证的范围。
- “有所改善”“达到题目门槛”“满足全部约束”“证明最优”是不同结论，分别要求对应证据。
- 表内通过只表示该条内容已被指定人员复核，不自动通过研究阶段或最终提交验收。阶段状态仍由 O 使用 `python mm.py stage ...` 管理。
- 换班时在 [交接模板](../交接/TEMPLATE.md) 中引用本轮写作卡、结果表、提交 SHA 和未解决项；接收人填写接收结论。
