# Meta-model-agent 操作入口

所有命令在仓库根目录执行，Python 3.10+。`mm.py` 仅转发到固定技能，不实现第二套状态机。默认 workspace 为本仓库；无须每位成员重新 init，克隆已有状态后使用 current / status。

```bash
python mm.py stage current
python mm.py stage status
python mm.py pipeline overview
python mm.py pipeline next
```

上游输出可能提示 `python scripts/...`，这里的 scripts 指 `.agents/skills/meta-model-agent/scripts/`；使用本页 mm.py 等价入口即可。

## 赛题导入前置

华为杯必须把原始题面与当届官方模板一起导入，并由用户或团队依据当届要求明确 AI 使用报告开关。当前 `pending` 保留未决定状态，不假定允许/禁止 AI。

```bash
python mm.py intake --problem "外部原件/题目.pdf" --template "外部原件/官方模板.docx" --ai-disclosure required
```

`required` 仅为命令示例，执行前必须确认；如果团队依据当届要求明确关闭，改用 `off`。附件可重复传入 --problem；数据管理以导入工具和当前阶段协议为准。不要把示例路径当成实际文件。

模板/当前竞赛 是技能自带参考，不能代替上传的当届官方模板。内置竞赛规则也是核验起点，不代表已核实 2026 年官方规则。

## 阶段收口

```bash
python mm.py stage begin DISCOVERY
python mm.py stage validate DISCOVERY
python mm.py stage gate_check DISCOVERY
python mm.py stage complete DISCOVERY --artifacts 问题分析.md
```

收到真实复核结论后才执行相应 checkpoint；这里不提供可直接复制的“已通过”占位批准。每阶段要完成规定产物、验证、门禁和需要的核验点，具体见技能当前阶段协议。

阶段顺序为 DISCOVERY、FORMULATION、COMPUTATION、EVIDENCE、SCHEMATICS、MANUSCRIPT、ASSURANCE。返回上游用 `python mm.py stage rework 阶段 --reason "实际原因"`，下游证据由状态机失效；不要沿用旧版 freeze 命令。

可选冠军模式：`python mm.py pipeline set-mode championship`。当前 standard 未改变；启用后按技能执行 MANUSCRIPT 后的独立多轮审稿，不能省略 ASSURANCE。

## 协作与工具

O 负责状态修改并串行集成；其他人用状态查询，按 Issue 范围交付。不要将四个人分别 init 后产生的状态 JSON 合并。阶段任务包由工具生成，不手工复制一份独立状态。

初次环境检查运行 `python 协作/工具/tool_locator.py xelatex drawio pdftoppm`。仓库未分发 .ttf/.ttc/.otf 字体；内置 LaTeX 模板涉及 simkai.ttf、SimSun、Times New Roman 等。使用者按本机环境和实际官方模板准备字体，正式阶段必须真实编译验证；当前不宣称编译就绪。
