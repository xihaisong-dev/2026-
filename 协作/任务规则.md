# 任务管理

默认使用 GitHub Issues 的“协作任务”模板：一个 assignee，正文明确接收人、范围、交付物、验收标准、截止时间和状态。

状态：TODO → DOING → REVIEW → DONE；未完成时均可进入 BLOCKED，解除后返回原阶段。交接已接收且 PR 已合并后才能 DONE / 关闭任务。

任务要可验收，例如“完成 q1 输入校验与基线运行”，不要只写“负责代码”。依赖明确写“依赖 #12”。状态以 Issue 正文为准；todo.md 只保留阶段入口，避免重复维护。

## 无网络或未启用 Issues

复制下列字段到 `协作/任务/LOCAL-YYYYMMDD-角色-NN.md`：

```text
编号：LOCAL-YYYYMMDD-角色-NN
目标：
负责人 / 接收人：
状态：TODO
截止时间（+08:00）：
输入版本 / 依赖：
修改范围 / 交付物：
验收条件：
分支 / PR / 交接单：
阻塞及恢复条件：
```

恢复联网后迁入 Issue，本地文件标记“已迁移”并只保留链接，停止双向维护。
