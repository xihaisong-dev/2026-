\section{模型评价与结论}
\subsection{模型特点}
本文以同一计算图表示为基础，按三个场景逐步扩展状态与约束：场景A把每个子图视为独立Task并令跨图数据经DDR；场景B引入同核复用和跨核同步；场景C进一步显式记录共享L2的FIFO状态与带宽竞争。这样的分层建模保留了问题之间可比较的划分、映射和顺序决策，又避免将某场景不存在的通信或缓存收益误用于另一场景。

求解采用结构化初解、关键路径优先调度与有界局部修复。连通分量、共享输入、双计算管道负载和缓存压力共同决定候选的结构；关键链等待与资源空隙决定局部调度；官方评估程序负责最终合法性和完成时间裁决。通过保留原方案、冻结预算及记录逐组结果，算法可区分预测收益与实际收益，适合在100图、1至5核的固定配置上复现。

\subsection{模型优点的边界化表述}
第一，三个问题共用统一的算子、张量与方案表示，场景变化由 Task 构造和事件服务规则承担。这样可以复用覆盖、无环与核心顺序检查，而不把场景 A 的每子图 DDR 规则硬塞给 B，也不把 C 的 L2 命中率写成独立优化变量。统一不是“用一套固定成本系数解释三问”，而是对相同的决策 $p$ 使用相应的正式评价器。式\eqref{eq:three-evaluators}把这种共性与差异分开，降低了跨问迁移时的概念错误。

第二，模型将\emph{静态结构}、\emph{局部预测}和\emph{官方结果}分为三个证据层。静态结构可以证明一个商图是否无环、某一分量是否主导算子数，不能证明其周期；局部预测可以决定有限候选的优先次序，不能直接替代已验证方案；官方结果可以确定指定参数下的 Makespan 与额外搬运，却不能证明全局最优。这样划界，使得每一个正面结论都可追溯到足够强的证据。尤其对共享 DDR 和 FIFO，线性边权代理易失真，因此最后一层正式评价至关重要。

第三，方案的主要目标和次要目标遵循字典序。这比把搬运字节随意乘上一个大常数并加到周期里更符合题意，因为二者量纲不同，常数若取值不当会让一字节差异压倒真实周期改善。定义
\begin{equation}\label{eq:lex-explicit}
(T_a,D_a)\prec(T_b,D_b)
\iff
\bigl[T_a<T_b\bigr]\lor
\bigl[T_a=T_b\ \land\ D_a<D_b\bigr].
\end{equation}
由此，只要 $T_a$ 比 $T_b$ 少一周期，即使 $D_a$ 略高，仍优先 $a$；两者周期完全相同才看搬运。由于官方周期是离散整数，这一判别可直接执行而不需要人为调节权重。在论文结果中某些方案的逻辑搬运上升而周期下降，正是式\eqref{eq:lex-explicit}主次关系的体现，而非模型自相矛盾。

第四，百图全量结果和逐例附录相互约束。平均加速比、总周期、逻辑额外搬运、Q3 同方案缓存效应分别从相同的五百行账本聚合；负例和相邻核数非单调也保留。这样的证据链允许读者从主文曲线一路追到一个算例、一种方案与一份官方评估记录。与只报告若干开发图相比，它更能检查候选规则是否在多种结构下稳定；但全量覆盖仍只覆盖赛题给定图集，不自动成为对未见图分布的统计保证。

\subsection{模型缺点、已观察到的失效及可操作改进}
成本预测仍是最主要的算法弱点。候选之间的共享 DDR 竞争不是独立子图时长的简单和：把一个 Task 提前可能改变所有同刻传输的服务份额，延后另一个更关键的读取；对问题三，命中改变的是事件的服务池，并可能改变完成顺序和后续 FIFO 队列。即便代理保留四条 Pipe 的局部依赖，如果冻结的背景状态与候选修改后的全局状态不同，排名仍可能错。问题一过去已有代理看好而官方接近四胜五负的审计现象，因此新邻域若仅依赖代理选择，会迅速耗尽有限预算而难以稳定提升。可操作的下一步是：固定同一完整候选池，逐对保存代理值与官方值，核对前二覆盖率、选择遗憾及误差最大的三类事件；仅对被证实误排的关键区域补充更精确的局部事件重放，最后仍用同预算正式评价验证结果。

模型的另一个缺点是缺少紧的、与划分无关的全局最优下界。式\eqref{eq:universal-compute-bound}严谨但忽略 DDR 与同步；条件带宽界和场景 A/B 路径界较具体，却随方案本身改变。若把它们直接拿去计算“当前距最优只差某百分比”，推理无效。未来可以尝试在聚合图上构造更强的资源割集下界，例如对\emph{每一种}合法切分都必经的张量集合求最小必传量，再把它与算子链、Pipe 工作量耦合。但这样的下界必须对所有可行方案成立，且求解下界本身不应比原题穷举还难。在尚未证明前，本文只用同版本官方对照评价启发式质量。

有限候选预算是求解效率与搜索质量的有意取舍，也造成可见的失败：问题二、三都有相邻核数退步，问题三有四组 L2 相对无 L2 的负例；在大量配置上增加一个搜索算子只带来持平，说明该算子可能重复了现有候选或挤掉有效基础搜索。可以把已验证的少核方案作为多核保底，但需确认增加一个空闲核心不改变评价语义，并从原预算中为这项新保底安排机会。对有主导分量的图，可在现有整分量方案取得实测收益后，才开放一次结构不同的细切候选；对很多小分量的图，保留完整分量分配和两 Pipe 负载均衡，不必固定给每张图相同的拆分机会。这种按结构和实测改善调整机会的策略应在正式规则冻结后做全百图对照，不能根据已见结果事后给个别图额外试验次数再与旧版比较。

大图端到端墙钟时间仍未全量证明满足题目建议的五至十分钟。现有最长热搜索约 $364$ 秒只是部分阶段；第 $67$ 图等大图的单核整图核内基准本身可能耗时很长。若仅把搜索次数削到很少而牺牲周期质量，虽然墙钟变短，也不符合主目标；若只重跑相同候选或重复核内准备，则增加墙钟而未扩大信息量。工程上可优先缓存相同输入与硬件下的官方核内准备结果、对不受局部动作影响的子图复用 Pipe 序、对规范相同的完整方案只作一次正式评价，并把冷启动、搜索与最终复核分别计时。这些操作要通过独立官方重放检查缓存键正确，不能为了提速跳过结果核验。

\subsection{可推广的求解思想与必须重新校准的部分}
对其它具有多核、私有片上存储和共享带宽的计算设备，可迁移的是四步：先把工作负载表示为带共享张量的有向依赖图；再针对硬件通信与同步语义生成结构不同的合法划分；用执行资源和关键输出的事件信息排序有限候选；最后用可信评价器按主次目标选择方案。这一框架尤其适用于“图规模大而精确整数规划不可直接求解、官方仿真较昂贵”的离散调度问题。并非只有神经网络算子可以抽象成类似的图，工作流或数据流作业也可能共享这一方法学。

不能直接移植的是所有数值常数、FIFO 状态方程和具体切图阈值。例如目标设备若提供跨 Task 的私有缓存保持，场景 A 中同核边界必须经 DDR 的前提就消失；若有网络互联而非共享 DDR，通信的拥塞资源会从一个全局池变成多条链路；若 L2 为组相联 LRU，完成时的 FIFO 淘汰式也不适用。对新设备应重新建立 Task 事件生成规则、服务池状态和存储容量，验证评价器与实际设备的关系，再把本文的有界结构搜索嵌入新规则。保持逻辑框架，不等于保证原来在一百图上的 $3.665903$、$4.264407$ 或 $4.364503$ 继续成立。

\subsection{主次目标、帕累托候选与可交付选择}
字典序使最终选择没有权重任意性，但搜索阶段仍有理由保留少量非最优的结构候选。假设候选 $p_a$ 的周期较短而搬运较多，另一个候选 $p_b$ 的周期较长而搬运较少；根据式\eqref{eq:lex-explicit}最终只能选择 $p_a$，但 $p_b$ 可能是后续局部修复更好的出发点：它较少的 DDR 字节可为迁核或拆分腾出通信预算。保留候选是\emph{搜索状态}的策略，不改变最终评分规则。若一次只保留当前字典序最优，所有局部动作都必须从 $p_a$ 出发，可能因邻域狭窄而无法到达 $p_b$ 附近的优质方案；若无限保留帕累托前沿，又会超过题目建议的求解时间。因此可仅保存结构差异显著的少数候选，并把它们的后续官方评价机会纳入总预算。

对两个方案定义弱支配：$p_a\preceq p_b$ 当且仅当 $T(p_a)\le T(p_b)$ 且 $D(p_a)\le D(p_b)$，并至少一个严格。若 $p_b$ 被支配，它在当前目标和两个单项指标上均不优于 $p_a$；但这仍不足以证明从 $p_b$ 出发的所有后继都不优，因为局部结构相异可产生不同的可达邻域。若两方案互不支配，选择 $T$ 更短者用于交付，同时仍可在固定小容量的工作池中保存另一者。这个区别防止把“保留多候选”误写成“改变赛题评分方式”。当前交付版的核心保证是已评价的最短周期方案输出；未来若引入有限帕累托工作池，必须比较相同总预算下的最终 $T$，而不能把更多评估次数带来的改善算作方法优势。

历史分布诊断与当前搬运账本也提醒，对于不同场景的方案不能把 $(T,D)$ 直接放入一个共同的帕累托前沿。场景 A 和 B 的 Task/COPY 构造不同，场景 C 虽和 B 使用相同的逻辑 $D$ 定义，但读取走 L2 或 DDR 的物理服务不同；若把 Q1 的 $D$ 与 Q3 的 $D$ 当作同一资源消耗严格比较，会忽略它们对应的带宽池差异。字典序仅在\emph{同一场景、同一图、同一核数、同一固定参数}下用于候选选择。跨场景的表格回答的是“各题规定的模型分别能达到什么数值”，而非在同一硬件上公平选择 A/B/C 模式的工程结论。

\subsection{复杂度与质量之间的可审查权衡}
若图有 $n$ 个可切算子、$q$ 个候选子图和 $e$ 条投影依赖，单次商图拓扑检验是 $O(q+e_\pi+e_\sigma)$；对固定划分，反向关键度递推也是同阶。一个朴素空隙插入会查看至多 $q+k$ 个位置，每次检查受影响顺序与依赖；若不复用局部状态，最坏可能多次重建商图。与这些多项式阶段相比，官方核内启发式可能在大图上插入大量换入换出，而全局事件仿真随同时在途搬运的到达、完成次数增长。求解时间因此更接近
\begin{equation}\label{eq:cost-accounting}
t_{\rm solve}
=t_{\rm parse}+t_{\rm seed}
+\sum_{j=1}^{B_{\rm distinct}}\!
\bigl(t_{\rm legal}^{(j)}+t_{\rm inner}^{(j)}+t_{\rm event}^{(j)}\bigr)
+t_{\rm replay},
\end{equation}
而不是仅用 $O(n+e)$ 概括。$B_{\rm distinct}$ 是真正不同并需要正式评估的候选数，名义槽位可能因重复而更大；缓存可以减少重复 $t_{\rm inner}$，但不能省略最后一次独立回放。式\eqref{eq:cost-accounting}使五至十分钟的要求可以被分阶段审计：若 $t_{\rm inner}$ 主导，应优先优化核内准备复用；若 $t_{\rm event}$ 主导，可优化同等语义下的事件队列实现；若 $B_{\rm distinct}$ 过多，则应校准排序和去重。盲目降低所有阶段的精度可能牺牲合法性或主目标。

搜索预算 $B$ 选得过低时，结构候选尚未覆盖关键布局；选得过高时，后续提案的边际收益可能接近零而 CPU 成本继续增长。可定义第 $b$ 次新增正式评价的实际增益 $g_b=T_{b-1}^{\rm best}-T_b^{\rm best}\ge0$。由于 incumbent 只接受更好方案，$g_b$ 非负，但这并不保证 $g_{b+1}\le g_b$：一次晚出现的结构候选仍可能带来大幅改善。由此不能用“最近三次均持平”作严格的搜索收敛证明。合理的停止规则是在预定硬预算内，结合过去一段候选的结构新颖性和实际收益，决定剩余机会投向何种邻域；若没有这些日志，就应保守维持基础搜索份额。对于本题一百图，所有这类自适应规则还须固定版本后全量对照，而不能在看见最终分数后临时修改某张图的预算。

当算法在同一图上对多个核数重复求解时，计算资源充足的本机或服务器可把\emph{不同 $(i,k)$ 配置}并行运行；这不改变每配置的候选预算，也不改变 NPU 方案周期。但是若多个进程同时争用主机内存、磁盘或官方评价器的缓存，观察到的墙钟秒数会随部署方式变化。因此提交中的“单用例十分钟”应在明确的主机硬件、并发数和冷/热状态下报告；把百图并行墙钟时长除以一百不能代表任何单个配置的求解时间。本文的全量成绩是方案执行周期的统计，与运行批次的服务器调度方式分离。

\subsection{结论}
三问分别保存了100图、1至5核的500份合法方案。五核逐图平均加速比分别为3.665903、4.264407、4.364503；问题三最终方案在同核下仅切换L2的平均时间比为1.030244。目标是降低实际完成周期，加速比用于按题目口径归纳结果；额外搬运在周期相同时进一步优化。
