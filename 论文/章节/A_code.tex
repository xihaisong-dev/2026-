\section{核心程序与复现入口}
本附录直接从仓库引用三问的\emph{当前提交入口}，避免把初版求解器误列为现行算法。完整源码、输入和官方评价程序随交付仓库提供。百图批量复现与校验由\path{q1_delivery_r02.py}、\path{q2_delivery_r07.py}及问题三冻结交付脚本与交接单约定。问题一入口调用\path{q1_experimental.py}和结构候选模块；问题二入口调用\path{q2_reserve_fast.py}；问题三入口调用\path{q3_solver.py}与\path{q3_neighborhood.py}。入口代码和核心模块应在相同提交版本下一起使用；纸面列表只是定位复现入口，不能替代仓库中的全部依赖。
\subsection{三问核心求解逻辑与参数}
以下伪代码对应当前交付程序的候选生成、官方评价与择优主循环。输入图、配置和官方评价器必须来自同一冻结版本；公式中的 $D$ 为官方逻辑额外搬运量。
\begin{enumerate}[leftmargin=2em]
\item \textbf{问题一（\path{q1_experimental.solve_experimental}）：}读取图并构造有向依赖及共享输入索引；生成整图、完整分量、受限拓扑切分等合法初解；按关键度与 Pipe 工作量映射到核心，并进行合法空隙插入；对规范指纹去重。保护基础划分机会后，在剩余预算中提出局部边界、映射与顺序联动候选。每次先验合法性，再用场景 A 官方评价返回 $(T^A,D)$；按字典序更新当前最优，输出方案并作独立回放。
\item \textbf{问题二（\path{q2_reserve_fast.solve}）：}将问题一结果仅作为结构种子，另保留整图备选；在场景 B 中重新估计同核驻留、跨核 COPY 与 $500$ 周期释放，生成六个结构候选；对主导分量按 $\chi(G)>0.5$ 的固定门控允许另一种布局，重复候选只按预设规则补位；最后提出至多四次合法的迁核加局部顺序修复。所有候选用场景 B 官方评价按 $(T^B,D)$ 选择，并独立回放。
\item \textbf{问题三（\path{q3_solver.solve}）：}问题二方案作为保底；先用场景 C 官方评价取得固定方案 L2 结果，扫描真实 FIFO 未命中和消费者所在子图；\path{q3_neighborhood.pool} 从有限核心迁移与合法插入位置提出至多四个不同候选。逐个用官方双带宽事件评价，以 $(T^{L2},D)$ 字典序更新，最终重放并复核 FIFO、内存峰值与搬运恒等式。问题三最终方案再由\path{q3_no_l2_replay.py} 在官方场景 B 评价器下重放一次，形成同方案无 L2 对照；这一步是结果复核，不是额外搜索机会。
\end{enumerate}
