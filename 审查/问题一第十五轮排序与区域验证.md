# 问题一第十五轮：预算台账、局部精确重排与有界区域搜索

2026-09-23，A 端原型实验，分支 `codex/q1-ranking-ledger`。本轮不变更正式阶段，不推广默认配置。既有原件与官方评估器保持原样。

## 实现与合同

- [x] 基础划分台账：记录 evaluated、duplicate（完整方案哈希与已有 evaluation_id）、infeasible；保留原调用顺序。四次构造机会不冒称四个不同评价，不强行重复评价以凑数。
- [x] 冻结池诊断：Spearman 平均秩处理并列；固定 label 打破代理并列；首选遗憾、前两名遗憾及最优覆盖率。单候选或常量向量 rho 为 null。
- [x] 局部精确重排：调用官方 `_build_scene_a_tasks` 的边界复制、Step1、Step2 溢出、Step3 核内准备，再按既定核心顺序近似回放；不调用全局事件循环，不使用候选官方结果排序。按完整划分含 Task ID 缓存两项，避免边界 ID/启发式并列依赖导致错误复用。尚未实现只重算受影响 Task。
- [x] 自适应扩区：4→8→12 Task，仍限512算子；候选不足6或没有代理收益才继续扩展。每个规模最多6种划分×2种顺序；采用结构去重，不承诺至少6个可行变体。
- [x] 有界多步修复：4 Task 区域，最多6步×4邻接边界探针，每算子最多移动一次；允许相对初始代理时长最多2%的暂时退步，保留最好前缀。所有候选验证商图与核心顺序联合无环，保持区域外划分、核心和相对顺序。

局部精确方案保持原始4 Task候选生成；扩区和多步模式另有结构去重，故这两组是机制包消融，不单独归因于尺寸或暂时退步一个参数。四种在线配置均固定官方预算12、种子0、一次区域替换机会；不挤掉基础粒度机会。局部准备耗时额外记录，不称同墙钟预算。

## 反例与五项成本机制

case_045/5核：原方案官方33313、精确重排33685。两方案局部精确回放32144→31951（代理认为改善193），官方反而增加372。全局残差1169→1734，增加565，超过局部收益。额外搬运557056→548864，且两者溢出搬运均为0。因此该反例不能归因于缓存溢出或总字节增加；误差位于局部回放之外的全局并发效应，需要进一步按官方DDR事件时间线定位，尚不声称完成唯一因果归因。

1. 子图边界：官方实际插入的 COPY 节点已进入局部成本；通信字节不直接作为 makespan 的等价目标。
2. 并行度：划分、核心分配、核心顺序共同决定等待；区域外冻结减少扰动，但也限制可到达解。
3. 共享输入：同核不同子图仍可能重复读取，不能仅按核心相同减免；合并是否获益由官方构图和评价确认。
4. Cube/Vector：采用官方核内 Pipe 调度得到的时长，避免简单累加各算子周期；仍未把全局DDR竞争精确传播到各Pipe。
5. 容量压力：官方Step2溢出已进入候选准备，融合不再假定必然收益。当前全划分准备缓存开销较高，尚未建立可证明安全的Task级增量键。

结论：预算证据和排序诊断已改善；局部精确成本具有可部署性，但并未独立改善本批最终目标，不能替换默认。扩区/多步各找到有限收益，仍有退步且开销显著增加。下一优先级是基于准备得到的传输阶段、Pipe依赖和真实字节量诊断全局共享DDR残差，再决定是否保留额外区域预算。
