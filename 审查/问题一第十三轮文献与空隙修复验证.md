# 问题一第十三轮：文献检索、瓶颈核查与区域空隙修复

A端作者自查；分支codex/q1-region-gap；2026-09-23。这是原型研究，不代表独立审核、正式阶段或全量性能验收。文献为定向跨站检索，不声称穷尽互联网。沿用官方评估器与审计输入，不采用暴力穷举。

## 当前瓶颈证据

1. **新邻域有效率低**：v12b的28次区域提案只有4次改善当时最优解；250个区域调度提案中200个通过构造/合法性检查。剩余50个未通过并不全是同一种错误，不能都算DDR问题。
2. **预测可信度有限**：历史顺序记录中，1811对预测与官方时间均非平局的候选，有762对次序相反。但本地时长观察随迭代更新，所以这只是跨轮次历史一致性诊断，不是固定模型排序错误率。不能把该比例当预测器精度。局部残差混合Pipe、复制、缓存影响，全局残差也不能直接等同DDR竞争造成的延迟。
3. **部分图结构和映射失衡**：048/5核最终197613 cycles，核心Task数[72,106,38,0,0]，共216个小Task、每个最多8算子。两核空闲是真实结果，但依赖和跨核等待可能使强制铺满五核更慢；下一步必须按官方时间验证合并/拆分/映射，不能用平均负载直接判优。
4. **区域修复遗漏时间空隙**：全局q1_insertion已经支持插入，但v12区域rebuild只有队尾追加；这给出了可隔离检验的实现改动。Task时间覆盖率平均约75.87%，其中包含传输与内部停顿，并非计算单元利用率，也不意味着剩余24.13%全可消除。
5. **预算机会成本仍存在**：固定12次预算下，新候选替换随机搜索，不保证保留基础的最优轨迹。v12已证明替换local_reschedule会破坏有效前缀，因此本轮只改变区域重建器，不改变预算位置。

诊断原始明细见v13-protocol/bottleneck_audit.json及final_plan_structure.json。

## 实际实现

新增region_gap特性及shared_region_gap配置，必须同时启用region。区域rebuild使用有序事件列表，逐Task、逐核心计算最早可行插入位置，然后贪心选择最早完成；不回溯、不枚举所有排列。间隙两侧保留同核等待，数据依赖按已分配核心计跨核释放。区域外核心归属及相对顺序由额外前驱边保持。

仍为最多4个Task/512个算子、最多6种区域映射×2种优先顺序=12个代理候选，每次求解最多一次区域提案，总12次官方评估。未增加官方候选预算。原区域追加策略保留为消融对照；默认方案不变。

48项测试通过。新增专门反例验证小任务确实可以填入依赖等待形成的空隙，并验证外部顺序不变、官方可执行、预算和当前最优保留。仓库检查0 errors，diff检查通过。

## 固定版本实验结果

## 接下来的优先级

1. 冻结同一成本观察状态，在同一个受限候选池内对比代理与官方排序；先修诊断，避免跨轮次代理值比较冒充固定模型精度。
2. 参考FlexFlow仿真思想研究共享DDR事件级近似，使用官方日志差分验证；只比较相同输入与映射，缓存边界ID/顺序也要计入。尚未实现，不能承诺收益。
3. 参考dagP构造保持无环的有界多步边界细化，而非只移动最大亲和的一条边；同时保留现有划分机会。对048这类碎任务/低核心使用图单独检验，避免强行负载均衡。
4. 扩大新图分层和多种子验证，再考虑自适应分配官方预算。所有新增方法须固定预算对照，不用每图事后挑最佳配置宣称统一算法收益。
