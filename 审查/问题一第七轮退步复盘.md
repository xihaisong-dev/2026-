# 问题一第七轮：三组退步的证据与预算修正

复盘对象：第六轮 insertion_rank 与 joint_cal，在 case_001/4核/种子1、case_093/4核/种子1、case_002/5核/种子0 的同12次候选预算结果。六份原始计划/完整评估/搜索日志哈希与诊断摘录保存在 `图表/runs/20260923-A-q1-v7-regression-audit/audit.json`。不修改旧结果。

## 不能把退步全部归为代理排序误判

| 配置 | 基础 → 联合校准时间 | 搜索轨迹证据 |
| --- | ---: | --- |
| case_001/4/1 | 65256 → 67313 | 基础第12次random_merge取得65256；联合校准预算分给联合拆分后未访问该方案。联合候选预测69117、实际67716，本身是高估而非乐观低估。 |
| case_093/4/1 | 30692 → 31203 | 基础后段random_merge取得30764，再local_reschedule到30692；联合搜索后段访问不同候选。其取得31203的联合拆分预测24360，确有局部/并发综合低估，但不能独立证明这就是最终退步的全部原因。 |
| case_002/5/0 | 60651 → 62065 | 初解和后续定向拆分均发生变化；基础后段directed_split找到60651。联合候选boundary预测66708低于拆分68076，但实际62101高于62065，出现36cycles的局部排名反转；该反转远小于最终1414cycles的差距，不能解释全部退步。 |

这些运行的候选集合、顺序与历史校准状态不同，不能直接用跨配置预测误差均值证明因果。缺少所有未评价候选的官方真值，也不能推断其潜在排名。真实代理误差存在，但新增搜索挤占原探索机会和提前校准改变初解同样重要。

## 分开看同步、Pipe、缓存和DDR

- 同步：固定方案预测与官方均使用前驱释放时间最大值和同核顺序，不累加跨核边数×1000。fixed_profile_wait_effect是在固定独立Task时长下的反事实回放，不代表可直接删掉的全部时间。
- Pipe：已保存六份最终方案逐核各Pipe实际繁忙周期。不同Pipe可重叠、核内不同Task串行，不能把所有Pipe繁忙周期简单求和当作makespan。计算结构下界与局部独立时长分开使用。
- 缓存：六个最终方案spill_added_copy_bytes均为0，因此缺少证据将这三组退步归因于溢出新增搬运。不能据此断言搜索中的每个候选都没有溢出或内存地址约束影响。
- DDR：case_001竞争事件542→549、case_093为873→884、case_002为746→672；第三组事件减少却变慢，事件计数不是拥塞时间，也不能作为主目标。完整官方时间线与实际完成时间仍是最终依据。

## 实施的修正与边界

新增guarded_joint：先保留ceil(75%×总候选预算)的基础搜索轨迹，期间只收集成本校准观测；之后才启用校准并插入联合候选。总预算仍相同，不通过额外官方调用伪造增益。自动测试验证前9次候选标签、完成时间、搬运量与12次基础搜索完全一致，且后段保留前段最优。

这不能保证恢复基础算法第10～12次才找到的好解。复跑case_001仍为67313，未修复该退步；case_093取得30480，优于原基础30692。case_002取得60664，相对基础60651仍差13cycles，虽小于旧联合校准的1414cycles差距，也不算完全修复。

补充分层验证揭示同类机制：case_048/4核基础第12次grain_0.25取得197613，新策略以联合候选替换了该次细粒度探索，最终204944。只保护前75%数量不能保护各类关键探索；该策略不适合默认替代。case_045的2～5核均改善，但这是单一高通信代理极端图，不能据此建立已经验证的通用“通信型图启用、链型图关闭”规则。

新增覆盖首先按100图结构选定四个规模层代表，覆盖M/V主导；再补充关键路径占比与张量字节/工作量极端图，名单在各自求解之前冻结。未以这些新图的求解成绩挑选样本。完整协议固定源码哈希、输入哈希、种子、核数、预算和90秒时限；超时另列，不当作差解或成功解。

后续判断以分层配对、旧退步回归和超时比例共同进行；保留失败结果，不因为仅有部分配对完成就宣称全量质量或正式验收。
