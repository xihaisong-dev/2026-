# 场景 A/B 候选评分的严格有效偏序等价证书（v2）

实现：`src/certified_evaluate.py`，版本 `prepared_effective_partial_order_v2`。原官方源码、冻结求解器与评估调用保持不变；包装层任务计数元数据更正见 `results/provenance/metadata_revision` 与 `results/source_revisions.json`。

## 条件与逐实例检查

仅考虑每个活动核心恰一个子图的候选。调用官方 A、B 的完整 Task Builder（包括官方 Step1、Step2、Step3），要求 A 的 Task 前驱全部为空，B 的跨核 COPY 链接为空，两边 cross_task_traffic 为零，完整 data_movement 字典相同。

逐核以 `(Pipe, 该 Pipe 内 FIFO 位置)` 唯一标识每个操作，比较全部操作数量、原计算操作身份、操作类型、Pipe、官方计算的执行工作量、DDR 带宽占用标志及内存峰值。原图计算操作 ID 必须逐位置相同；生成操作的绝对新 ID 可不同。每条 Pipe 的顺序完整且覆盖全部操作，prepared 序列必须完整，seq_pos 必须正确；实际 pred/succ 必须互为镜像。

动态模拟器的**有效依赖图**是 prepared 中所有 op_preds 边加各 Pipe 的相邻 FIFO 边。memory-reuse、真实数据依赖、Spill 等产生的边已全部包含在 prepared op_preds 中。

首先进行有严格路径依据的冗余边消除：对每个目标操作，同一源 Pipe 的多个前驱只保留 FIFO 位置最大的一个，因为源 Pipe 的更早操作通过 FIFO 链必先完成；目标自身 Pipe 上更早的前驱由目标的直接 FIFO 前驱隐含。目标同 Pipe 上的自环或更晚前驱一律拒绝，不删除。然后显式保留每个目标的直接 FIFO 前驱。

若两图经上述变换后的**完整前驱对象**精确相等，则通过。若仍不同，对差异边做双向可达性检查：A 独有的每条边必须在 B 的有效图中已有路径；B 独有的每条边必须在 A 中已有路径。通过 Kahn 排序检查 DAG，以 Python 整数 bitset 在逆拓扑序精确计算可达集合。只有所有差异边均被另一图蕴含时通过。SHA256 只记录审计标识，实际判断使用完整对象相等和逐边可达检查。

任何结构条件、描述符、搬运字典、偏序检查不满足，或官方准备过程报错，都直接回退官方 A 完整评估。

## 为什么足够

两图通过检查意味着每个操作在同一核心/Pipe/FIFO位置上具有相同工作量与带宽类型，且两套有效依赖图的传递闭包相同。删除的 FIFO 支配边具有显式路径；双向可达检查则证明剩余差异边也只是冗余约束。因而任何满足前驱约束的已完成集合，在两图中产生同一可发射集合。

A 的每核唯一 Task 无前驱，在 t=0 激活；B 的 Task 同样从 t=0 开始，且没有跨核释放等待。A 的 Task 结束扫描不会释放后续 Task，也不会影响其他核心；B 的外部同步机制为空。两程序按相同核心和 Pipe 顺序退休、推进队列和发射 FIFO 队首。每个 Pipe 同时只有一个队首候选，所以全局 seq 不同 Pipe 间的排列不构成额外发射自由度。

DDR 公平共享工作量、并发数、取整规则完全相同。对事件时刻归纳，两者完成集合、可发射集合、运行集合、DDR 剩余工作和下一事件时刻一一对应。因此最终 makespan 相同。完整搬运量由准备阶段字典相等单独保证。

## 使用边界与审计

返回的 B 结果保留其原始 scene='B'，仅用于候选评分，不重标成 A。最终选中的代理候选由 runner 再次调用官方 A，断言 makespan 与完整 data_movement 字典一致，然后保存该真实官方 A JSON 为正式结果。不能把两种场景整体说成等价，也不能把证书解释为无需验证的经验规律。

元数据保存版本、是否通过、失败原因、逐核原签名 hash、有效签名 hash、证明途径、差异边验证数、准备与模拟时间、整体证书 hash。例：case014/4核 Pipe均衡候选原 prepared 边集在4核均不同，但经 FIFO 支配消除后全部有效前驱对象精确相等，4核通过，证书时间26.88秒。这里不把证书准备时间冒充完整求解时间。
