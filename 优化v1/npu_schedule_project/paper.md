% 基于结构感知划分与评估反馈的多核神经网络调度

# 摘要

多核神经网络处理器的并行收益受到图依赖、共享带宽与私有缓存约束。针对无核间同步、具有核间同步及共享只读 L2 三种场景，本文联合优化子图划分、核心分配与核内顺序，采用结构候选构造与官方离散事件评估相结合的确定性算法。

针对问题一，识别计算依赖图的弱连通分量与无分支链，构造完整分量分配、分批和拓扑窗口切分候选；结合关键路径优先列表调度，以执行时间、额外搬运量依次选优。5 核平均加速比为 3.652。

针对问题二，将同核子图合并为一个 Task 以保留中间数据复用，增加共享输入顺序候选，并由官方程序处理跨核同步、缓存换入换出及流水线等待。5 核平均加速比为 3.910。

针对问题三，采用容量 1 MiB、读带宽 250 bytes/cycle 的 FIFO 只读 Cache，固定问题二方案进行有无 L2 的成对评估。5 核平均相对加速比为 1.031，平均字节命中率为 23.52%。结合搬运分解与流水线时间线，解释命中率与实际时延收益的差异。

全部实验使用附件 100 个正式计算图与原始固定配置，1500 组结果均通过官方评估及独立核验。完整方案、逐例指标和复现脚本随文提供，支持对三种场景下并行、通信与缓存之间的权衡进行追溯分析。

**关键词**：多核 NPU；有向无环图；数据复用；列表调度；缓存约束；离散事件评估

# 1 问题重述

## 1.1 问题背景

神经网络中的分块矩阵运算、向量运算和数据搬运可以表示为有向无环计算图。多核 NPU 的每个核心具有矩阵计算单元、向量计算单元以及两个搬运流水线，核心之间共享 DDR。矩阵与向量运算能够在同核重叠执行，多个核心也可以同时工作，但需要满足输入就绪、流水线互斥和私有缓存容量约束。DDR 读写共享固定的总带宽，不能将各核心的搬运时间独立相加后直接作为真实执行时间。

本题给定操作与张量构成的二部图[6]。操作具有流水线类型和计算周期，张量具有逻辑存储位置与字节数。需要将非 COPY_IN/COPY_OUT 操作划分为子图，为每个子图指定核心，并给出各核心的子图执行顺序。官方程序根据方案补充搬运操作、插入必要换入换出，并在共享资源下模拟执行。优化目标以 Makespan 为主，同时控制新增搬运量。

## 1.2 三个问题的任务

问题一对应场景 A。每个子图独立成为一个 Task，Task 之间不保留私有缓存数据。因此，跨子图依赖即使位于同一核心也必须经过 DDR，且同核 Task 切换等待 100 cycles、跨核前驱完成后等待 1000 cycles。需要综合考虑切图粒度、并行空间和 Task 启动开销。

问题二对应场景 B。同一核心上的全部子图合并为一个 Task，同核中间结果可以继续保留在 L1/UB 中；仅跨核依赖需要 COPY_OUT 与 COPY_IN，并在源 COPY_OUT 完成后增加 500 cycles 同步等待。此时核心归属直接影响数据局部性，较长的数据存活期又可能增加缓存压力。

问题三在场景 B 上增加全核共享的只读 FIFO L2。其容量与带宽固定，命中不改变 FIFO 次序，未命中搬入完成后才将数据放入 Cache。需要比较相同核数、相同方案下有无 L2 的执行差异，并说明容量限制、访问时序与命中带宽如何共同影响收益。

## 1.3 相关研究与本文思路

列表调度通过确定任务优先级并选择预计完成最早的处理器，降低大规模 DAG 调度的搜索成本。HEFT 是这一类方法的代表[1]。无环 DAG 划分进一步要求压缩后的分区依赖仍保持无环，避免仅优化割边与负载而产生不可执行的分区[2]。本文借鉴关键路径排序与无环分区思想，针对题目同构多流水线结构构造候选，而不将静态通信估计直接作为最终性能。

有限快速存储与数据搬运的关系可以通过 I/O 复杂度模型分析[3]，DAG 调度顺序也会改变内存峰值[4]。这说明子图越大并不一定越优：合并可以降低边界搬运，却可能使核内调度插入更多 spill。Roofline 对计算与带宽约束的区分[5]，为解释加速饱和提供了参考。本题直接给定操作周期而非 FLOP 数，本文因此使用周期负载和字节流量分析瓶颈，不构造硬件实测吞吐曲线。

本文将决策分成候选构造与精确评估两个层次。候选构造利用图结构、流水线负载和通信代价快速缩小搜索范围；精确评估完整保留官方的存储管理、流水线 FIFO、共享带宽及同步规则。该结构适合题目给定的离线调度任务，也便于定位方案失败原因和核对每一个实验数值。

# 2 模型假设

本文沿用题目硬件与执行语义，不额外引入未给出的硬件能力。具体约定如下。

（1）输入图、操作周期和张量大小均取附件值，输入数据在一次调度期间不发生变化。核心同构，计算操作不可抢占、不可拆分，各操作只执行一次；由评估器引入的 COPY 和 spill 按其规则执行。

（2）PIPE_M、PIPE_V、PIPE_MTE2、PIPE_MTE3 各自串行，不同流水线可以并行。计算周期不随核心编号变化；访问 DDR 或 Cache 的实际完成时间由当时带宽竞争决定。

（3）L1 与 UB 是每核独立资源，容量不可互相借用。容量可行性按官方程序的虚拟字节额度与内存复用依赖检查，不另加地址碎片或内存整理模型。

（4）问题一的 Task 之间清空私有缓存；问题二、三同核子图合并后保留依赖关系和可复用数据。跨核同步只按规定延迟计入，不增加额外消息带宽或故障概率。

（5）L2 完全遵循官方 FIFO 行为，不预取、不合并同时发生的冷未命中访问，也不将命中视为零成本。命中读与 DDR 读写进入两个独立共享带宽池。

（6）采用确定性启发式搜索。所有用例都参与给定实例的求解与评估，不设置训练集与测试集划分，不将这组实验解释为学习模型的样本外泛化验证。

## 4.2 统一决策与评价模型

令方案 $x=(a,b,\pi)$。操作归属要求每个计算操作恰好对应一个子图，每个非空子图恰好出现在一个核心的调度表中。令 $G_S(a)$ 为对子图收缩得到的依赖图，则基本合法性要求为

$$a:V_C\rightarrow\{0,\ldots,m-1\},\quad b:\{0,\ldots,m-1\}\rightarrow\{0,\ldots,n-1\},\quad G_S(a)\text{ 为 DAG}.\tag{1}$$

同核顺序必须与子图依赖相容。实际评估还包含内存复用边和逐 Pipe FIFO 边，因此式（1）只是结构合法性的必要条件。对每个候选，仍需调用官方程序校验最终扩展执行图，任何出现全局等待环的候选均不参与选优。

以官方评估函数 $F_r$ 表示场景 $r$ 下的完整执行过程。本文采用词典序目标

$$x_r^*=\mathop{\arg\min}_{x\in\mathcal X_r}\bigl(T_r(x),D_{\mathrm{add},r}(x)\bigr),\qquad T_r(x)=F_r(G,x;\theta_r).\tag{2}$$

这里 $\mathcal X_r$ 是已生成并通过评估的有限候选集，$\theta_r$ 为固定配置。因此 $x_r^*$ 表示候选集中最好的可行解，不代表整个组合优化空间的全局最优解。式（2）用于问题一、二的方案选择；问题三固定问题二的胜出方案进行配对评估。目标不将 cycles 与 bytes 直接相加，也不需要人为选择两种单位之间的权重。

对扩展图中的普通计算操作，完成时刻为 $f_v=s_v+\max(1,p_v)$，与官方对零周期操作的处理一致。若 $u$ 是 $v$ 的前驱，则 $s_v\geq f_u$；同核同 Pipe 的操作按官方确定的 FIFO 次序串行执行。设 $R_{k,z}(\tau)$ 为时刻 $\tau$ 在核心 $k$、存储区域 $z$ 驻留的张量实例，则

$$\sum_{t\in R_{k,L1}(\tau)}d_t\leq524288,\qquad\sum_{t\in R_{k,UB}(\tau)}d_t\leq131072.\tag{3}$$

驻留开始、最后一次使用完成与释放都按评估器的执行事件更新。发生容量压力时，核内步骤按照未来使用位置换出张量，必要时写入 DDR 并在下次使用前换入。由此引入的 COPY 同样消耗共享带宽，不作为免费操作。

令同一时刻处于 DDR 搬运中的操作数为 $m_D(\tau)$。在该数目不变的事件区间内，各搬运公平分享 DDR 带宽；若以独占带宽时的剩余周期工作量 $w_j$ 表示第 $j$ 个搬运，则

$$\frac{\mathrm dw_j}{\mathrm d\tau}=-\frac{1}{m_D(\tau)},\qquad B_D=60\ \mathrm{bytes/cycle}.\tag{4}$$

DDR 搬运发射时，参考工作量初始化为 $w_j(s_j)=\max(1,\lceil d_j/B_D\rceil)$。每次搬运加入或完成都重新结算剩余工作量，预计完成时刻向上取整到周期。该表示与题目评估器一致，不能用“张量大小除以 60”代替全部最终搬运时间。

## 4.3 场景 A 的边界与 Task 约束

场景 A 中所有跨子图张量均经 DDR 中转，包括同一核心上前后两个子图之间的依赖。若 Task $j$ 的激活时刻为 $A_j$、完成时刻为 $F_j$，其同核前一 Task 为 $j^-$，同核与跨核前驱集合分别为 $P_j^\mathrm{same}$、$P_j^\mathrm{cross}$，则

$$A_j\geq\max\left\{F_{j^-}+100,\ \max_{i\in P_j^\mathrm{same}}F_i,\ \max_{i\in P_j^\mathrm{cross}}(F_i+1000)\right\}.\tag{5}$$

不存在的约束项不参与最大值计算，首个 Task 不承担同核前序切换等待。全局合法性还要求 Task 数据依赖边与各核心相邻 Task 顺序边的并集无环；仅检查同核直接依赖先后关系并不充分。式（5）说明过细切图会增加额外等待；另一方面，过度聚合又可能降低并行空间或增加 spill。因此需要同时保留多个切分粒度，再用实际执行时间判定。

额外搬运量采用官方口径

$$D_\mathrm{add}=D_\mathrm{sch}-D_0=D_\mathrm{partition}+D_\mathrm{spill}.\tag{6}$$

其中，$D_\mathrm{partition}$ 包含边界通信与输入复制所增加的搬运，$D_\mathrm{spill}$ 是缓存换出换入引入的额外搬运。一个张量被多个操作使用时，不能直接对所有依赖边累加字节数作为式（6）；真实值取决于张量被复制到多少个 Task，以及是否可共享既有副本。

## 4.4 结构感知候选构造



![](figures/fig01_method.png){width=15.5cm}

图2 结构感知候选构造与官方评估选优流程



算法首先在计算依赖图上求弱连通分量。对每个分量 $g$，累加四条 Pipe 的给定周期负载，得到向量 $\boldsymbol W_g$。在保持分量完整的候选中，同一核心分配到的所有分量聚合为一个子图，可消除这些分量之间不必要的 Task 切换。设置分量轮转分配作为朴素对照，同时构造按累计总负载分配、按最大 Pipe 负载分配的候选。

用于优先级排序的分量标量权重定义为

$$\widehat p_g=\max_q W_{g,q}+0.08\sum_qW_{g,q}.\tag{7}$$

式（7）以最忙 Pipe 的负载为主，加入总工作量作为次级区分。系数 0.08 用于候选优先级和完成时间的代理估计，不是学习参数，也不将该估计当作最终 Task 时长。负载均衡候选均按式（7）降序访问分量：总负载候选选择当前累计总周期最小的核心；Pipe 均衡候选优先选择加入当前分量后最大 Pipe 负载最小的核心，平局按已有总负载及核心编号打破。

场景 A 另设置完整分量分批候选：当分量数不少于 $2n$，且最大分量周期不超过平均每核总周期的 1.15 倍时，沿用 Pipe 均衡的核心分配，将各核分量按最小操作编号排序，再按目标 256 个计算操作组装 Task。单个超过该目标的分量仍保持完整。该操作数目标只控制候选粒度，不替代 L1/UB 字节容量约束；不同批次可能重复读取共享输入并增加 100 cycles 的同核切换等待，是否采用仍由官方执行时间决定。

若最大分量的总计算周期超过平均每核总负载的 1.15 倍，则触发图内切分。第一类切分将“源节点只有一个后继、目标节点只有一个前驱”的连续边合并成无分支链，以保持强顺序依赖的局部性。第二类切分按拓扑深度分窗，再在每个窗口内求弱连通分量。窗口编号沿依赖边单调不减，同一窗口内不同弱连通分量之间不存在依赖，因而此构造保持子图依赖无环。

对已经得到的子图 DAG，从后向前计算关键路径优先级

$$r_g=\widehat p_g+\max_{h\in\operatorname{succ}(g)}r_h.\tag{8}$$

无后继时，式（8）中相应最大项取 0。每一步只从前驱已被安排的就绪集合中选择 $r_g$ 最大者。设 $\widehat A_k$ 为该核当前代理完成时刻、$\tau_s$ 为同核 Task 等待，针对核心 $k$，估计其最早完成时间

$$\widehat F_{g,k}=\widehat p_g+\max\left\{\widehat A_k+\tau_s\mathbf1\{\widehat A_k>0\},\ \max_{h\in\operatorname{pred}(g)}\left(\widehat F_h+\lambda\widehat c_{h,g,k}\right)\right\}.\tag{9}$$

当子图 $g$ 没有前驱时，式（9）中关于前驱集合的最大值项取 0。

通信估计 $\widehat c$ 是同步等待与搬运代理时间之和：异核等待在场景 A、B 下分别取 1000、500 cycles，同核等待 $\tau_s$ 分别取 100、0 cycles；跨组搬运按两倍割边字节数除以 60 估计。场景 A 下无论两子图是否同核，均考虑该搬运项；场景 B 下同核依赖的搬运项为零。链候选使用 $\lambda=0.65$，标准深度窗口候选使用 $\lambda=1$；$\lambda$ 同时缩放前驱项中的等待与搬运估计，而不缩放核尾部的 $\tau_s$。算法选择代理完成最早的核心，并在队尾追加子图，未采用空闲间隙插入。割边估计可能重复计入共享张量，只承担候选引导功能；最后仍按式（2）选优。

## 4.5 求解流程与复杂度

输入为原始 JSON、核心数和场景编号。首先建立生产者、消费者索引及计算依赖投影；随后生成结构候选、去除完全重复的方案，并补入整图置于一个子图、其余核心空闲的保底候选。对每个候选按下述证书路径或直接评估路径评分，保留成功结果及失败原因。选择最小 Makespan，若相同则选择额外搬运较少者；胜出方案保存对应场景的官方评估结果，并输出仅包含 node_to_subgraph 与 core_schedules 的规定 JSON。各核数独立构造候选，不继承低核数的已选方案，因此不预设加速曲线随核数严格单调。

本次采用 standard 候选预算。对超过 10,000 个计算操作节点的大图，不生成 LPT 与输入复用次序候选，保留分量轮转、Pipe 均衡以及满足各自结构触发条件的链切分和场景 A 分量分批候选；大图的深度窗口仅保留场景 A 的 16 层窗口和场景 B 的 4 层窗口。未超过该规模阈值的图在触发细分时使用 4、8、16 层窗口。候选数量随结构触发与方案去重而变化，并非每个图都评估相同数量的候选。所有参数保持固定，候选生成不读取用例编号进行人工分组；官方评估失败的候选记录错误原因后剔除。整图单核方案提供安全回退，多核方案可以保留空闲核心。相同方案按完整映射与核心顺序去重，避免重复评估。最终方案与每个候选的指标均随代码包保存。

为减少部分场景 A 候选的评分开销，另外设置逐候选的有效执行偏序等价证书。证书只适用于每核至多一个子图、场景 A 的 Task 无前驱、场景 B 无跨核连接且两侧跨 Task 搬运量均为零的方案。分别调用未经修改的两种场景官方构建过程，完成核内排序、spill 插入及内存复用补边后，以“Pipe 与该 Pipe 内的 FIFO 位置”对齐操作。随后精确比较原计算操作身份、操作类型、Pipe、官方参考工作量、DDR 标志、各 Pipe 的完整操作顺序和存储峰值，并要求完整搬运统计字典一致。

真正决定就绪条件的有效依赖图由全部 prepared 前驱边与各 Pipe 的相邻 FIFO 边共同构成。对每个目标操作，同一来源 Pipe 上较早的前驱可由该 Pipe 上最晚的前驱及 FIFO 链蕴含；目标自身 Pipe 上更早的前驱由其直接 FIFO 前驱蕴含，自环或更晚前驱则直接拒绝。仅消除这些具有明确路径证明的冗余边，并显式保留直接 FIFO 前驱。若两图的完整有效前驱对象相同，即可确认偏序一致；若仍有差异，则通过拓扑排序与整数位集合计算精确可达性，要求 A 独有的每条边均在 B 中存在对应路径，且 B 独有的每条边也均被 A 蕴含。哈希只用于审计追踪，不代替完整对象比较或逐边可达性证明。

上述条件构成逐实例的充分条件，而不要求原始 prepared 边集逐边相同。两套有效依赖图的传递闭包相同，因此在相应已完成集合下具有相同可发射集合。两种模拟均从时刻零开始，沿相同核心与 Pipe 顺序退休并发射队首操作，DDR 共享工作量与周期取整规则也相同；没有后续 Task 或跨核等待时，场景 A 的 Task 管理不会额外改变释放条件。按事件归纳，两者运行状态与下一事件时刻一一对应，最终 Makespan 相同；搬运指标由完整字典比较另行保证。

任一证书条件失败或构建报错时，直接使用官方场景 A 完整评分；通过时只允许复用无 Cache 的官方场景 B 候选分数。若这种候选最终获选，仍重新调用官方场景 A，断言其 Makespan 和完整搬运统计与评分结果完全一致后，才保存正式场景 A 输出。因此，候选集内的比较指标不变，问题一最终时间线始终由官方场景 A 产生；该做法不表示两种硬件场景普遍等价，也不将场景 B 的结果改标签作为场景 A 结果。

设投影图有 $N$ 个计算操作和 $M$ 条依赖边。图遍历、分量和深度计算为 $O(N+M)$；使用堆的拓扑与就绪列表为 $O((N+M)\log N)$。给定 $K$ 个候选，列表分配还需要遍历候选子图及其前驱，并比较至多 5 个核心。官方模拟的成本与 spill 后的扩展图规模相关，不能只用原始节点数线性估计。证书的精确可达检查仅在 FIFO 支配化简后仍有差异时启用，其时间与存储开销同样取决于扩展图规模，并计入总评估成本。实验分别记录候选生成时间和总评估时间，避免将模拟器及证书开销误认为算法本身的图划分开销。

# 5 问题二 同核数据复用与同步调度

## 5.1 场景变化与模型调整

场景 B 将一个核心上的全部子图合并为一个 Task，子图数量本身不再等于 Task 数量。同核依赖保持核内数据流，因此切图主要影响核内排序与跨核边界，而不会自动缩小同核合并 Task 的整体存储工作集。

对具有唯一生产核心的中间张量 $t$，设该核心为 $k_t$，令 $m_t$ 表示除 $k_t$ 外使用张量 $t$ 的不同消费者核心数。官方程序针对每个不同的源核—目标核连接分别插入一对 COPY_OUT/COPY_IN。因此，只统计跨核连接所增加的 COPY 字节数时，有

$$D_\mathrm{cross}=2\sum_t d_t m_t.\tag{11}$$

式（11）包含对每个目标核分别产生的源端写回，不能采用“一次源核写回加多次目标核读入”的计数。若张量存在多个生产核心，则对所有不同的生产核—消费核对分别计 $2d_t$。外部输入复制、最终输出和 spill 另行统计，整体额外搬运量仍取式（6）的官方结果字段。

若面向目标核心 $k$ 的源写回操作为 $o_{t,k}$、目标读入操作为 $i_{t,k}$，则跨核同步条件变为

$$s_{i_{t,k}}\geq f_{o_{t,k}}+500.\tag{12}$$

这里的起点是 COPY_OUT 完成，而非源核整个 Task 完成。不同核心之间可以因此形成更细粒度的生产者消费者重叠。式（3）的 L1/UB 约束、四 Pipe 互斥以及 DDR 公平共享规则继续适用。

## 5.2 复用与驻留之间的权衡

同核复用可减少重复写回与读取，但驻留时间从一次局部计算延长到后续消费者完成。若为保留未来数据而挤占当前操作输出空间，核内调度仍可能将其换出。因而优化时需要同时观察 $D_\mathrm{partition}$ 与 $D_\mathrm{spill}$：前者下降并不保证两者之和下降，也不保证任务时长下降。

算法在分量聚合、负载分配、链划分和深度窗口候选之外，增加按共享 DDR 输入身份排列分量的候选。先统计输入张量出现在多少个分量中，再按频次及张量编号形成确定性的顺序，使关联输入的使用有机会相邻。该规则只控制子图优先级，不改变运算依赖，不自行实施缓存预取。

对于独立分量候选，可以将各核心的分量聚合为一个子图，也可以保留多个子图以约束核内优先级。两者在场景 B 中最终仍是一核一个 Task，但步骤一的顺序可能不同，从而改变张量生命周期与 spill。本文将这种变化交由官方评估决定，不预先认为“保留更多子图”一定更优。

## 5.3 全局可执行性检查

仅检查原始 DAG 和子图 DAG 无环不足以保证场景 B 可执行。例如，核心 0 的某条 Pipe 队首在等待核心 1 的写回，而核心 1 的该写回又受另一条 Pipe 的队首或内存复用依赖限制，组合起来可能出现等待环。官方程序将真实依赖、地址复用依赖、Pipe FIFO 与跨核 COPY 依赖合成全局图，并在模拟前检查环路。

本文保留该检查，失败候选直接记录为不可行，不将超时、中间结果或局部 Makespan 当作有效结果。最终方案输出后，还独立核对节点覆盖、子图唯一调度和结果字段一致性，并保存原始执行时间线用于审查。

# 6 问题三 共享只读 L2 下的调度分析

## 6.1 FIFO Cache 模型

问题三保持场景 B 的方案、核内执行规则与跨核延迟，仅增加 Cache。令 Cache 容量 $C_C=1048576$ bytes，读带宽 $B_C=250$ bytes/cycle。对于一次符合缓存条件的 COPY_IN，在发射时用逻辑张量 ID 查询：若已驻留则命中，进入 Cache 读带宽池；若未驻留则进入 DDR 带宽池，并在完成后插入 Cache。查询范围包括外部输入、跨核读入以及 spill 后换入，并不限于原始图输入；不同物理换入版本通过逻辑张量 ID 关联。

容量不足时，按最早插入顺序淘汰；命中不刷新顺序。单个张量大于 Cache 容量时不驻留。若多个核心同时请求尚未完成首次搬入的张量，这些请求均可能未命中，因为评估器没有在途请求合并。因此，共享输入多不意味着必然获得高命中率。

若同一事件区间内有 $m_C(\tau)$ 个 Cache 搬运，则其剩余参考工作量遵循与式（4）相同的公平共享关系，但带宽池与 DDR 分离。DDR 上的 COPY_OUT 不会直接变成 Cache 命中读，也不占 Cache 读带宽。

## 6.2 命中率与数据搬运统计

官方命中率按字节定义。设可查询 Cache 的 COPY_IN 集合为 $I_C$，命中集合为 $H_C$，则

$$h=\frac{\sum_{j\in H_C}d_j}{\sum_{j\in I_C}d_j}.\tag{14}$$

式（14）分母为零时命中率取零。命中次数率与式（14）不同。较大的张量命中可能贡献较高的字节命中率，即使命中次数较少。正文展示逐用例命中率的算术平均，同时在汇总表中保留合并字节口径，避免把二者混淆。

有 Cache 时，官方 scheduled_copy_bytes 与 added_copy_bytes 仍统计逻辑 COPY 工作量，命中不会从这两个字段直接扣除。用于解释 DDR 压力时，另定义派生量

$$D_\mathrm{DDR}^\mathrm{physical}=D_\mathrm{sch}-D_H.\tag{15}$$

本文表格中的“额外搬运量”始终使用官方 $D_\mathrm{add}$，派生的物理 DDR 量只用于单独分析。问题二方案原样用于问题三时，两者的逻辑搬运构造相同，而部分搬入可以由 L2 服务；不能以逻辑额外搬运量未下降为由断言 L2 无效。

## 6.3 配对实验与容量带宽解释

对每个用例和核数，固定问题二选出的方案 $x_{i,n}^{B}$，分别运行场景 B 与 Cache 评估器，定义

$$R_{i,n}^{C/B}=\frac{T_B(G_i,x_{i,n}^{B})}{T_C(G_i,x_{i,n}^{B})},\qquad\overline R_n^{C/B}=\frac{1}{100}\sum_iR_{i,n}^{C/B}.\tag{16}$$

这种配对方式不额外为 L2 单独更换方案，能够回答给定调度下只读 Cache 的净效果。代价是本文并未搜索 L2 特有方案空间的最好解，相关结论限定在已选场景 B 方案上。对所有核数均报告真实 Cache 结果，包括 1 核情况下可能由 spill 重读产生的命中。

在所有固定配置主实验中，不改动容量与带宽参数。容量影响通过共享输入规模、实际命中及 FIFO 淘汰机制解释：活跃共享输入超出 1 MiB 时，较晚访问可能已经错过驻留期；即使总输入较大，只要短期复用集合较小，也仍可能取得较高命中率。决定命中的对象是访问时序下的驻留集合，而非整个图所有输入大小之和。

单次独占服务的带宽比为 $B_C/B_D=250/60\approx4.167$，这是相同工作量从 DDR 改由 L2 服务时忽略周期取整的理想带宽比，不是整图加速比。设 $W_M$、$W_V$ 分别为全部矩阵与向量操作的给定周期总量，对于给定方案，一组必要的资源下界为

$$T\geq\max\left\{\frac{W_M}{n},\frac{W_V}{n},\frac{D_\mathrm{DDR}^\mathrm{physical}}{60},\frac{D_H}{250}\right\}.\tag{17}$$

该下界不包含关键路径、同步等待与内存复用约束，只用于识别不可能突破的资源限制，不作为精确最优值。即使有命中，若关键路径主要由计算或同步决定，Makespan 的改善也可能很小。反之，减轻 DDR 争用可以同时缩短多个核心的等待，使局部命中产生全局收益。

# 8 模型评价与结论

## 8.1 模型与算法特点

本文围绕题目执行语义构造统一模型，将划分、核心归属和子图次序一起提交到官方评估。与仅依赖负载均衡的方案相比，结构候选保留了无分支链和弱连通分量内部数据流；与仅依赖静态通信估计的方案相比，最终选优计入了真实共享带宽、私有缓存换入换出及 FIFO 等待。所有正式用例均保留最终方案和原始指标，论文结果能够逐条追溯。

同一实现适配 1～5 核和三个场景。算法不依赖训练样本，也不通过修改官方缓存或带宽参数改善指标。图结构分析负责生成可解释的候选，精确评估负责区分看似负载均衡但实际搬运或等待较多的方案。

## 8.2 局限与改进方向

首先，有限候选集不覆盖所有可行划分，不能提供全局最优保证或严格最优性间隙。其次，权重 0.08、结构阈值 1.15 及窗口宽度是固定启发式设置，本次实验没有证明这些参数在其他图分布上仍然最优。再次，问题三采用问题二方案的配对比较，未专门优化 FIFO 复用距离与首次读取时序；因此还有针对 L2 的进一步搜索空间。

此外，官方核内调度顺序与 spill 策略是题目指定的执行组成部分。多核收益中可能包含对该启发式顺序的改善，不能直接外推为真实商用 NPU 的实测性能。后续可以围绕关键路径上的通信边开展局部合并、迁移与顺序交换，并用增量评估减少重复模拟成本；这些属于后续工作，未计入本文结果。

## 8.3 结论

本文建立了覆盖三种硬件场景的切图、分核与顺序联合模型，采用结构候选构造和官方精确评估完成 100 个正式计算图的求解。场景 A 与场景 B 的 5 核平均加速比分别为 3.652 和 3.910；固定场景 B 方案后，只读 L2 的 5 核平均相对加速比为 1.031，平均字节命中率为 23.52%。实验说明，图划分需要同时考虑独立分量、Pipe 负载、数据复用与容量压力；共享 Cache 的作用则需要通过同方案成对评估判断。本文结论适用于附件图集合、固定硬件参数与指定评估语义，完整方案、逐例结果和复现代码一并给出。
