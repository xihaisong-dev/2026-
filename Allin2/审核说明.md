## 2. 成绩定义

只比较问题一、5 核。单个 case 的加速比定义为：

`speedup = T1 / T5`

其中 `T1` 是该 case 的单核完工时间，`T5` 是 5 核方案的完工时间。100 个 case 的平均加速比是 100 个单题加速比的算术平均，不是平均 `T1` 除以平均 `T5`。

官方候选选择依据为三元组，按字典序取最小：

`(makespan, added_copy_bytes, method_name)`

非法候选不能成为胜者，并单独计入 `invalid_candidate_count`。

与原始 Allin 基线比较时，绝对增量定义为：

`Allin2 speedup - Allin baseline speedup`

基线应按相同 case 对齐，不能用 Allin2 的单核时间直接代替原工程的 5 核基线加速比。

## 4. 实际算法

Allin2 在 Allin/BuildAb 基础候选上追加结构化候选，再由未修改的官方评估器统一评测和选优。主要流程如下：

1. 根据 DAG 节点、边、深度、弱连通分量、张量位置和内存约束生成候选计划。
2. 保留基础候选，并追加变宽窗口、搜索式变宽窗口、PEFT/HEFT 插入式放置、管线分段、分量分组、管线向量负载平衡和内存批处理等候选。
3. 使用指纹去重，避免同一计划被重复评估。
4. 必要时加入整图候选，并记录候选来源和方法名。
5. 对每个候选调用包内 `official/` 评估器，按 `(makespan, added_copy_bytes, method_name)` 选出最终方案。
6. 将最终完工时间、基线完工时间、加速比、候选统计和完整方法信息写入交付汇总。

关键实现文件包括：

- `npu_schedule_project/src/solver.py`：基础调度和候选生成主流程。
- `npu_schedule_project/src/extra_candidates.py`、`extra_candidates_ext.py`：追加结构候选。
- `npu_schedule_project/src/calibrated_heft.py`：校准时长的 HEFT 候选。
- `npu_schedule_project/src/ls_p1n5.py`：问题一 5 核的计划级局部搜索。
- `npu_schedule_project/src/allin2_layer.py`：Allin2 的额外候选层。
- `npu_schedule_project/src/run_experiments.py`：运行、评估、汇总和结果写出。
- `npu_schedule_project/official/`：官方问题评估器。

代码应按图结构和固定约束运行，不应依赖 case 编号、预存答案或结果表查表。最终方法必须经过官方评估器确认，不能仅凭启发式估计的时间写入成绩。

## 7. 复核运行方式

Python 优先使用 conda 环境。短流程可在代码包目录执行：

```powershell
conda activate <项目使用的环境>
Set-Location 'Z:\YuyanData2\codex\数学建模2026\9.25优化v2\Allin2\npu_schedule_project'
python -u src/run_experiments.py --mode full --problems 1 --cores 5 --budget standard --output <新的空输出目录>
```

正式长时间测试应放在远程设备 `jishishan-remote` 上执行：

```powershell
ssh jishishan-remote
conda activate <项目使用的环境>
Set-Location '远程代码目录\\npu_schedule_project'
python -u src/run_experiments.py --mode full --problems 1 --cores 5 --workers <按资源监控调整> --budget standard --output '<新的远程输出目录>'
```

远程并发调整规则：CPU 和内存都低于 85% 时逐步增加并发；任一项超过 95% 时减少并发；介于两者之间时保持当前并发。不要多个 agent 共用同一个输出目录，也不要把未完成的 Stage A 输出直接标为正式结果。
